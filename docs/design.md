## 1. コアコンセプト

**お絵かき ＋ お世話。**

自分の描いた絵が、そのまま3Dのおへやで暮らし始める。その子の世話をしながら、少しずつ暮らしを広げていく。

要素を残すかどうかの判断基準：

- 描く理由になるか（描いたものが目に見えて使われる・反応が返ってくる）
- お世話の手触りにつながるか（相棒と触れ合う時間が増えるか）
- どちらにも当てはまらない要素は、削除か後回しにする

## 2. 「描く」の扱いと魔法のペン

### 2.1 世界の決まりごと

- ゲームの中に出てくる絵（相棒・料理・飾りなど）は、**すべてプレイヤーが描いたもの**という扱いにする。
- 描く行為は**入力のためのインターフェース**として扱い、ストーリーは付けない（現行版でもメタな入力UIになっている）。

### 2.2 魔法のペン

- 描く場面では、どこでも次の2択を並べる。
  - **自分で描く**：お絵かきエディタを開く
  - **魔法のペンにおまかせ**：用意された絵の中から選ぶ（現行の「元絵を選ぶ」の言い換え）
- 演出は大雑把でよい：ペンのアイコンが斜めにシャカシャカ動く → 絵がフェードインする（1秒ほど）。一筆ずつ描く再現や、質感へのこだわりは不要。
- ペンが描いた絵には、手直しも保存・共有もできない（2.7）。自分の絵にしたいときは、白紙から自分で描く。
- 用意する絵は仮素材で構わない。後から差し替えられる構成にする（6章）。

### 2.3 文言の統一

「プリセット」「元絵」「初期の〇〇」のように、用意された素材を感じさせる言葉は使わない。「魔法のペンが描いた」「描き直す」などに統一する。

### 2.4 自分で描いたものへのボーナス

描かない人への罰ではなく、描いた人へのご褒美にする。

- 相棒：自作のごはんやおもちゃに、特別なリアクションとセリフ
- お客さま：自作の料理に、特別な感想セリフ（現行版は客ごとに固定のセリフ）
- 経済：自作の料理を初めて出すと「新作ボーナス」（現行は＋80で、ペンの料理にも付いていた）
- 具体的な数値は実装時に調整する

### 2.5 よそで描いた絵を持ち込む：魔法のペンに見本を見せる（実装済み）

画像ファイルの持ち込みは、魔法のペンの選択肢「**見本を見せる**」として入れる。遊ぶ人が見せた絵をもとに、ペンが描いた、という扱いにする。「自分で描く」は、本当にこの画面で描いたものだけになる。

- **入口**：魔法のペンの絵の一覧の先頭に、「見本を見せる」の枠を1つ置く。用意された絵と同じ並びの中にあるので、描く場面の2択は増えない
- **見せ方**：ファイルを選ぶ操作だと、ことばと絵の両方で伝える
  - アイコン：写真の絵に、上向きの矢印を重ねたもの。ペンのアイコンと並んでも区別がつくこと
  - ことば：「見本を見せる」＋小さく「写真・画像から」
- **流れ**：端末の「ファイルを選ぶ」（スマホでは写真の一覧やカメラ）→ いつものシャカシャカ → ふわっと出る →「これにする／ほかの絵にする」。用意された絵を選んだときと同じ
- **取り込み方**：縦横の比を保って 512×512 に収める。透明の部分は残す。紙を撮った写真のために、描き上がりの画面に「白いところを消す」の切り替えを1つだけ出す
- **扱い**：魔法のペンが描いた絵として数える。自作のいいことは付かず、手直しも保存・共有もできない（2.7）
- **容量**：持ち込んだ絵もセーブに入る。512×512 に縮めてから保存する。あわせて、保存に失敗したときの知らせを入れる（いまは黙って失敗する）
- **複雑さ**（5.1）：足す操作は「見本を見せる」と「白いところを消す」の2つ

### 2.6 スケッチブック：描いた絵を見返し、保存・共有する（実装済み）

「思い出」を「**スケッチブック**」に広げる。これまで描いた絵を全部見返せて、自分で描いた絵は1枚ずつ保存・共有できる。相棒の自慢より、「ここは絵を描く場所」と伝わることを大事にする。

**並ぶもの**

- 相棒・料理・コンビニの商品（ごはん・おもちゃ）・ポスター、手直し前の相棒、お別れした子
- **描いた順（古い順）に並べる**。見返すための画面なので、ノートを1ページ目からめくるように古いものから並べる。向きは、レビューなどで多く指摘があれば見直す
- 並べる基準は**描いた時刻だけ**。種類や、いまの相棒かどうかで並びを変えない（いまの相棒を先頭に固定しない。代わりに「いまの相棒」と添える）
- 描き直す前の相棒は、その絵を描いた時刻の位置に並ぶ（描き直した時刻ではない）
- 描いた時刻の記録がない絵（記録を始める前に描いた絵）は、いちばん古い側にまとめる
- それぞれに「相棒」「料理」などの種類と、描いた日（○日め）を小さく添える
- 自分で描いた絵には、右上に小さなペンの印をつける。魔法のペンが描いた絵も並ぶが、印はなく、保存・共有はできない（用意した絵やコラボの絵を外に出さないため）

**1枚を開くと**

- 大きく表示し、名前・種類・描いた日を出す
- **保存する**：背景が透明の画像ファイル（PNG）にする。受け取った人は、そのまま 2.5 の「見本を見せる」で自分のゲームに持ち込める。「描く → 見せる → 誰かの世界に入る」が一周する
- **共有する**：スマホの共有画面を開く。添える文は「おえかき暮らしで描いた○○」＋サイトのアドレス程度。共有画面がない端末では「保存する」だけ出す
- サーバーには何も上げない。artifacts のプレビューでは保存も共有もできないことがあるので、確かめるのは GitHub Pages 版

**入口と、ことばの差し替え**

- HUD の「思い出」ボタンを「スケッチブック」にした。アイコンはノート。ボタンの数は変わらない。幅 400px 未満では、HUD の上の段を1行に収めるためアイコンだけにする
- 「思い出」という言葉は、画面・README・この設計書とも「スケッチブック」にそろえた（7.1 のマイルストーン1の記録だけは、当時の名前のまま）
- セーブの中の名前（`memories`）は変えない。今のセーブがそのまま読めるように

**データ**

- スケッチブック専用の置き場所は作らず、セーブの中の相棒・メニュー・商品・ポスター・描き直す前とお別れした子の記録（セーブの memories）からその都度集める（絵を二重に持たない）
- 絵を作ったときに、描いた日（○日め。表示用）と描いた時刻（`drawnAt`。並べ替え用）を一緒に記録する。描き直すときは、前の絵の時刻をスケッチブックの記録に引き継ぐ
- ゲーム内の「○日め」は1日に何枚も描くと同じになるので、並べ替えには使わない。今までの絵は日にちがないので、日にちは出さない

### 2.7 魔法のペンが描いた絵は、手を入れない・外に出さない（決定・実装済み）

魔法のペンが描いた絵（用意された絵・見本を見せて描いた絵・コラボの絵）は、**手直し（描き足し）も、保存・共有もできない**。手を入れたり外に出したりできるのは、自分で描いた絵だけにする。

- **理由1：権利**。用意した絵やコラボの絵、ほかの人の画像を見本にした絵が、描き足されたり、ゲームの外へ持ち出されたりしないようにする
- **理由2：わかりやすさ**。「自分の絵」＝自分で描いたもの、と決まりが1つになる。自作のいいこと（2.4）とも食い違わない

| できること | 自分で描いた絵 | 魔法のペンの絵 |
| --- | --- | --- |
| ゲームの中で使う | できる | できる |
| スケッチブックで見る | できる | できる（印はつかない。印は自分で描いた絵だけ） |
| 手直し（描き足し） | できる | できない |
| 保存・共有 | できる | できない |
| 白紙から描き直す（相棒の、はじめの3日間） | できる | できる（別の絵に替えるだけで、元の絵には手を入れない） |

この決まりで変わるところ：

- **魔法のペンの描き上がり**：ボタンは「これにする／ほかの絵にする」の2つ。いまある「自分で描き直す」（ペンの絵を下絵にして描く）はなくす。自分で描きたいときは、最初の2択で「自分で描く」を選び、白紙から描く
- **相棒のメニュー**：魔法のペンの子には「手直し」を出さない。はじめの3日間の「白紙から描き直す」は出す
- **スケッチブック**：魔法のペンの絵は見るだけ（2.6）
- **データ**：決まりが全員同じなので、相棒ごとに許す・許さないを持つ必要はない（3.8 の `allow` はなくした）
- 実装：#5（手直し）・#6（見本）・#7（スケッチブックでの保存・共有）

### 3.4 ミニゲームの扱い

料理を作る・お風呂・おもちゃで遊ぶなど、その場面だけの操作が必要なものは「ミニゲーム」としてまとめ、ゲーム本体の設計から切り離す。マイルストーン1で、すべてのミニゲームを本実装にした。どれも全画面で行い、長押し・ダブルタップは使わない（4.5）。

- **共通の約束**
  - 渡すもの：お題（例：作る料理、使うおもちゃ）と、対象の相棒
  - 受け取るもの：結果（完成／やめた）と、任意で出来ばえ（例：よい／ふつう）
  - 本体はミニゲームの中身を知らない。受け取った結果だけを、売上や相棒の状態に反映する
- **出来ばえと報酬**：出来ばえは「よい」「ふつう」（料理だけ「失敗」もある）。遊び・お風呂・迎えに行くには失敗がない。報酬は3段：完成で基本、「よい」で上乗せ、自分で描いたものでさらに上乗せ
- **画面の形**：見出し（ナビゲーションバーと同じく中央寄せ。左のボタンと重なるときだけ右へずれ、長いときは文節で折り返す）、操作の説明、進み具合（回数か工程の丸＋バー）、絵の枠、終わったら「おしまい」ボタン。工程が変わったら、指を一度離すまで判定しない
- 「なでる」はミニゲームにしない（相棒に直接触れる、コアの操作なので本体で扱う）

| ミニゲーム | お題 | 遊び方 | 「よい」の条件 | 結果の使い道 |
| --- | --- | --- | --- | --- |
| 料理：注ぐ（飲みもの） | 注文の料理 | ドラッグで傾け、線のあいだで離す | 70〜88%で止める（こぼすと失敗） | 完成で「運ぶ」が使える。「よい」でチップ（売上の20%）、失敗はお客さまの反応が変わる |
| 料理：焼く（ごはんもの） | 注文の料理 | 動く目もりをまんなかでタップ ×3 | 2回以上ぴったり | 同上 |
| 料理：切る（しょっぱいもの） | 注文の料理 | 点線に沿ってスワイプ ×3 | 2回以上まっすぐ | 同上 |
| 料理：飾る（甘いもの） | 注文の料理 | 料理の上をタップしてトッピング ×6 | いつも「よい」 | 同上 |
| お風呂 | — | ぬらす → 泡 → 流す → 水滴を吹きとばす | 40秒以内 | 汚れが落ち、具合の悪さも治る。「よい」でごきげん・なかよしが多め |
| ボール | 使うおもちゃ | 引っぱって離して投げる。待っている相棒がキャッチ ×3 | キャッチ2回以上 | ごきげん・なかよしが上がる。「よい」で多め、自作のおもちゃでさらに多め |
| 猫じゃらし | 使うおもちゃ | 振って、ぴたっと止めると飛びつく ×5 | 大ジャンプ3回以上 | 同上 |
| ぬいぐるみ | 使うおもちゃ | わたして、ハートが大きいときにタップ ×4 | ぴったり3回以上 | 同上 |
| 迎えに行く | — | かくれんぼ。耳がのぞく場所をタップして3回見つける | 外れ2回以内 | 逃げた状態が直る（出来ばえはセリフだけ変わる） |

### 3.5 ハラハラモード

病気・お別れ・脱走などのマイナス要素は、選んだ人だけが遊ぶ「ハラハラモード」として残す。通常モードはゆるい暮らしのままにする。

- **ご褒美**：獲得するコインと、ステータスのプラスに倍率をかける（例：1.5倍。値は調整）
- **ペナルティ**：放置すると発生する。汚れの放置→病気→お別れ、遊ばない・なかよしが低い→脱走（現行版の仕組みを参考にする）
- **放置の時間**：現行版と同じく、遊んでいる間だけ時計が進む（アプリを閉じている間にお別れにはならない）。ポップアップ・ミニゲーム・お絵かきの間も止まる
- **ペナルティまでの時間**：よごれたまま10分で病気、病気のまま5分でお別れ、8分なでも遊びもしないと脱走（なかよし・ごきげんが低いときだけ）。1回遊ぶ間にお風呂が1回いるくらいの目安。数値は `data.js` の `HARAHARA`
- **切り替え**：ゲーム中いつでも設定から切り替えられる。ただし、反映は「次の日から」にする（危なくなったときだけ通常モードに戻して、稼ぐときだけハラハラにする使い方を防ぐため）
- ハラハラモード中は、HUDのどこかに小さくモードの印を出す
- お別れした子の絵と名前はスケッチブックに残す（描いた絵は消さない）

### 3.6 相棒の名前・性格・見た目（提案）

- **名前と性格は、最初に決めたら固定**する。その子らしさの土台になり、愛着がわきやすい。
- **絵は「手直し」だけできる（自分で描いた子のみ。魔法のペンの子は手直しできない：2.7）。** 描き直すときは、今の絵が下絵として入った状態から始まり、白紙から別の子に描き替えることはできない。
- 手直し前の絵はスケッチブックに残し、あとから見返せるようにする（描き足していくことを、その子の成長や着替えとして楽しめる）。
- 例外として、はじめの数日（例：3日目まで）は白紙から描き直せるようにする。最初の絵を後悔してやめてしまうのを防ぐため。

### 3.7 行ける場所・コンビニ・バッグ

- **行ける場所**（上部の切り替え）：おへや／カフェ／コンビニ。お庭・おさんぽはここに足す候補。場所は4つまで。引っ越しのような「操作」は場所にしない。
- **コンビニ**：貯めたコインの使い道。ごはんとおもちゃを買う。
  - 最初の商品はごはん3種・おもちゃ3種。ごはんは使うとなくなり、おもちゃは1つ買えば何度でも遊べる
  - 「新しく描く」で商品を増やせる（上限24個）。自分で描いた商品は3割引き、魔法のペンの商品は定価
  - おもちゃは種類（ボール／猫じゃらし／ぬいぐるみ）ごとにミニゲームが変わる。自作するときは種類を選んで、ミニゲームを決める
- **バッグ**：おへやのボタン。買ったごはんとおもちゃを選んで使う（ごはん代をその場で払う仕組みは廃止）。自作のものは特別なセリフと、なかよしの上がり幅が増える。はじめはクッキー2つとボールを持っている
- **お部屋（模様替え）**：ポスターを描く、引っ越し先を見る、をまとめる
- **相棒の手直し**：ステータス欄を押すと出るメニューから
- **スケッチブック**：日数の右の「スケッチブック」ボタンから。これまでの絵（描き直す前の相棒・お別れした子も）が並ぶ（2.6）

### 3.8 相棒の気持ちの見せ方（決定・実装済み）

相棒の状態は、数値のバーではなく**「気持ち」**で見せる。**どの相棒も同じ決まりで見せる**（自分で描いた子・魔法のペンの子・コラボの子を分けない）。土台は「頭の上の記号」と「体の動き」で、絵が1枚でも伝わる。表情の差分の絵がある子は、その上で絵も差し替える。

**気持ちは「ふつう」＋4つ**（5.1 の「種類は4つまで」に収める）

| 気持ち | いつ | 頭の上の記号 | 体の動き |
| --- | --- | --- | --- |
| ふつう | ほかに当てはまらないとき | なし | ゆっくり歩く |
| ごきげん | ごきげんが高いとき | 音符 | 弾むように歩く |
| うれしい | なでた・遊んだ・ごはんの直後（数秒だけ） | ハート | ぴょんと跳ねる |
| しょんぼり | おなかがすいた・よごれた・さみしい・具合が悪い | もやもや（黒い線のぐちゃぐちゃ） | 小さく縮こまり、動きが遅い |
| すねる | ハラハラモードで長く放っておかれた | ぷんぷん（左下から出た煙が1つ、ぽんとふくらむ） | その場で足ぶみし、こちらを向かない |

- いくつも当てはまるときは、うれしい ＞ すねる ＞ しょんぼり ＞ ごきげん ＞ ふつう の順で1つだけ出す
- 気持ちは毎回いまの状態から決め、セーブには入れない（決め方は `store.js`、見せ方は画面側）
- **ふつうモードでも同じように出す**。病気やお別れは起きないが、「お風呂に入れてほしい」「かまってほしい」が見えることが、お世話の手がかりになる

**切り替わる目安**（数値は `data.js` の `FEELING` にまとめ、あとで調整する）

| 気持ち | 目安 |
| --- | --- |
| ごきげん | ごきげんが 70 以上 |
| うれしい | なでた・遊んだ・ごはん・お風呂のあと 5 秒 |
| しょんぼり | 次のどれか。おなかが 30 未満／よごれが「病気になるまで」の半分を過ぎた／さみしさが「逃げ出すまで」の半分を過ぎた（ふつうモードのとき）／具合が悪い |
| すねる | ハラハラモードで、さみしさが「逃げ出すまで」の半分を過ぎた。なでる・遊ぶなどで戻る |

- ハラハラモードでは、さみしさは「しょんぼり（さみしい）」ではなく「すねる」として出る（放っておくと逃げ出す手前、という知らせ）
- 逃げた・お別れした、など相棒がそこにいないときは、気持ちを出さない。ステータス欄はいまと同じ表示（「外に出ている」など）

**見せる場所**

- **3D の相棒**：頭の上の記号・体の動き・（差分があれば）絵の差し替え
- **ステータス欄**：バーをやめ、相棒の小さな絵＋気持ちのことば（「ごきげん」など）にする。しょんぼりのときだけ、理由のアイコン（おなか・よごれ・さみしい・具合）を出して、何をすればいいかわかるようにする。常に見える数値は「コイン・日数・相棒の気持ち」の3つになる（5.1）
- **くわしい数値**：仲よし度などは、ステータス欄から開く相棒のメニューの中だけに置く
- **話しているとき**（吹き出しが出ている間）：口あけの差分があれば口パク、なければ小さく上下に揺れる

**絵の差分の枠（あれば使う・なければ代わりを使う）**

| 枠 | 使う場面 | ないときの代わり |
| --- | --- | --- |
| 基本（必ずある） | いつも | — |
| 基本・口あけ | 話している間、基本と交互に | 揺れで代用 |
| にこにこ | ごきげん | 基本 |
| にこにこ・口あけ | ごきげんで話している間 | 基本・口あけ → 揺れ |
| うれしい | うれしい | にこにこ → 基本 |
| かなしい | しょんぼり | 基本 |
| おこり | すねる | かなしい → 基本 |

- 届いているコラボの差分（普通目・笑顔 × 口開け・口閉じ、うれしい・怒り・悲しみ）は、この7枠にそのまま当てはまる。一部だけでも、ない枠は代わりで埋まる
- 記号と動きは、差分がある子にも出す。差分は「足し算」で、見せ方の土台は全員同じ。記号は頭の右上に、絵に少しかかるくらいの小ささで出す（吹き出しは頭の真上）
- 音符とハート（よい気持ち）は出しっぱなしにせず、ときどき浮かび上がって消える。もやもやとぷんぷん（世話がいる気持ち）は、戻るまで出し続ける（ぷんぷんは、ときどきぽんと出なおす）
- 差分は特定の子だけの特別扱いにしない。自分で描いた子も同じ枠を使えるようにする（いずれ相棒のメニューに「表情を描く」を置き、枠ごとに描き足せる）

**データの持ち方**

- 魔法のペンの相棒の一覧の1行：`{ name, src, faces?, credit? }`
  - `faces`：差分の枠ごとの絵（`talk`・`smile`・`smileTalk`・`happy`・`sad`・`angry`）。どれも省略できる
  - `credit`：作者などの表記（コラボの子）
- 差分の絵は、基本と同じ大きさ・同じ位置合わせで作る（差し替えたときに体がずれない）
- セーブ：魔法のペンの子は、セーブに入っている「絵の場所」（`src`）で一覧の行を探し、差分はそこから引く。セーブは変えない（絵ファイルの名前を変えない決まり〈6.1〉があるので、場所で探せる）。自分で描いた子の差分は、将来 `pet.faces` に入れる
- 枠と代わりの決まりは `data.js` の `FACE_SLOTS`・`FEELING_FACE`、どの絵を出すかは `store.js` の `petFaces`（実装済み）
- 話している間：吹き出しが出ている間、口あけの絵があれば基本と交互に（1秒に7回ほど）、なければ小さく上下に揺れる（実装済み）

**記号の絵**

- 頭の上の記号（音符・ハート・もやもや・ぷんぷん）は、まず仮の線画を SVG で用意する。魔法のペンの絵と同じく、**同じ名前のファイルを置き換えるだけで手描きに差し替えられる**ようにする

**表情の差分の入れ方**

- 差分の枠と「ないときの代わり」の仕組みを先に作り、差分の絵はまだどの子にも入れない
- 入れるときは、絵を `assets/pen/` に置き、魔法のペンの相棒の一覧の行に `faces: { smile: '…', … }` を足すだけ（実装済み）。手順は `data.js` のコメントと 6.1
- コラボの子は、3人とも7枚の差分をすべて使っている（#24。基本の絵は「普通目」）。元の絵と一覧の書き方は `art/collab/README.md`

**作る順**（プルリクエストを3つに分ける）

1. 気持ちの決め方（`store.js`）と、ステータス欄の作り替え（バーをやめる。くわしい数値は相棒のメニューへ）
2. 3D の相棒に、頭の上の記号と体の動き
3. 話している間の揺れと、表情の差分の仕組み

### 3.9 飾る絵をためておく：ポスターを選べるようにする（決定・実装済み）

描いたポスターは消さずにためておき、模様替えで**どれを飾るか選べる**ようにする。いまはポスターの置き場が1つしかなく、描き直すと前の絵が消える（スケッチブックからも消える）。「描いたものは消えない」を、飾り全体の決まりにする。

**模様替え → ポスター**

- 一覧の先頭に「新しく描く」。そのあとに、これまでのポスターが新しい順に並ぶ。いま飾っている1枚には「かざっている」の印
- ポスターを押すと、それに飾り替える。「はずす」で何も飾らない状態にもできる
- 「新しく描く」で描いた絵（自分で描く／魔法のペン／見本）は一覧に足し、そのまま飾る。魔法のペンの同じ絵を2回選んだときは1枚にまとめる

**ためておける数：カフェのメニューと同じ扱い**

- 12枚まで（カフェのメニューと同じ数）。いっぱいのときは「新しく描く」を押せなくし、上限に達していることを添える。描き終わってから入らない、ということがないようにする
- ためた絵をしまう（消す）操作は、まだ作らない。ゲームが勝手に古い絵を消すこともしない
- 上限の数と、いっぱいのときの扱い（しまう・入れ替えなど）は、メニューとポスターでそろえて別に決める（8章）

**スケッチブック**

- ためてあるポスターが全部並ぶ。飾っている1枚には「かざっている」と添える

**データ**

- ポスターの一覧 `posters: [{ id, image, self, drawnDay }]` と、飾っているもの `poster: id`（なければ null）
- いまのセーブの `poster`（絵そのもの）は、読み込んだときに一覧の1枚目へ移して、それを飾っていることにする

**その先への広げ方**

- 3.3 で額縁やラグなど飾りの種類を増やすときも、同じ「種類ごとの一覧＋どれを置くか」の形にする（例：`decor: { poster: […], rug: […] }` と `placed: { poster: id, rug: id }`）。今回はポスターだけを作り、この形に移りやすい名前にしておく
- 足す操作は「選ぶ」「はずす」の2つ（5.1 の「新しい要素1つにつき3種類まで」に収まる）。「しまう」を足すときも3つに収まる

### 3.10 法的表示（実装済み）

設定のいちばん下（開発用の上）に「法的表示」を置き、ゲームの権利と、外から持ってきたものの表記をまとめて見せる。

**書くこと**

- ゲームの名前と、制作者の表記（`© 2026 SyafuChan3333`）
- 「あなたがゲームの中で描いた絵は、あなたのものです」。プレイヤーの絵はその人のブラウザの中にしかなく、ゲームの側には届かない。表記は制作者が作ったもの（コード・魔法のペンの絵・文言）だけに向ける
- 外から持ってきたもの：キャラクター（コラボの相棒）・ライブラリ・フォント・音楽・効果音の順に、名前・作者・ライセンス・リンク
- 「All rights reserved」は書かない（いまは法的な効き目がなく、プレイヤーの絵まで主張しているように読めるおそれがある）

**データ（`data.js`）**

- `LEGAL`：ゲームの名前と、制作者の表記
- `LEGAL_KINDS`：並べる種類と、その見出し。並びもこの順
- `LEGAL_CREDITS`：外から持ってきたもの。1行 `{ kind, name, by, license?, url?, licenseUrl? }`。**ライブラリや素材を足したら、ここに1行足す**
- キャラクターは `LEGAL_CREDITS` に書かない。コラボの相棒（`VT_COMPANIONS`）と、`credit` を持つ魔法のペンの相棒から自動で並ぶ（3.8 の `credit`）。いまのコラボの子は名前だけ。先方に表記を確認できたら、一覧の行に `credit: '© ○○'` を足せば出る
- 音楽と効果音は `public/assets/audio/` のもの（元の記録は `public/assets/audio/CREDITS.txt`。3.11）

### 3.11 音（実装済み）

**BGM**（甘茶の音楽工房。ループする曲）

| 場所 | 曲 |
| --- | --- |
| おへや・コンビニ | 日向ぼっこ（`hinatabokko.mp3`） |
| カフェ | のほほん喫茶（`nohohonkissa.mp3`） |

- 場所を移ると、曲をゆっくり入れ替える（同じ曲なら続ける）
- ミニゲームとお絵かきの間は、その場所の曲を小さくして流し続ける
- 画面を離れている間（ほかのアプリに切り替えたときなど）は止める

**効果音**（Kenney Interface Sounds〈CC0〉と Tスタ）

| 鳴らす名前 | ファイル | 使う場面 |
| --- | --- | --- |
| `tap` | `tap.ogg` | ボタンなど |
| `happy` | `happy.ogg` | 喜んだ・うまくいった |
| `pet` | `pet.ogg`（Tスタ「ぴょこ・その１」） | なでた・さわった・相棒の声。Kenney の音では重く聞こえたので差し替えた |
| `done` | `complete.ogg` | できた・出せた |

- **鳴らし続ける音**（`loopSe(名前)` で鳴らし始め、返ってくる `stop()` で止める）：音の区切りは `audio.js` の効果音の一覧に書き、鳴らす側は名前だけで呼ぶ
  - `clip: [はじめ, おわり]`：ファイルのこの部分だけを使う（長い音を短く切る）
  - `loop: [はじめ, おわり]`：区間ループ。前がイントロ、後ろがアウトロ。鳴らし始めにイントロ、`stop()` でアウトロを鳴らす（イントロの途中で止めても、イントロは最後まで）。くり返しは Web Audio の loop で、つなぎ目が正確。アウトロはループの終わりを待たず、すぐ重ねてつなぐ
  - `every: 秒`：短い音を一定の間隔でくり返す（`vary` で高さを少しばらつかせる）
  - `stop({ now: true })` はアウトロを待たずにすぐ止める（ミニゲームをやめたとき）
- お風呂での使い方
  - 「ぬらす」「洗い流す」：シャワーに指を当てている間、`shower.mp3`（Pixabay）。`loop: [0, 19.28]` で最後の無音をくり返さない
  - 「泡をつける」：こすっている間、`bubble.mp3`（On-Jin）を 0.15 秒に切って 0.5 秒ごと。手が止まって0.25秒で止める
  - 「ブロー」：最初の水てきを飛ばしたら `dryer.mp3`（Pixabay）。スイッチを入れる音 → 回る音のくり返し（`loop: [1.2, 4.8]`）→ 最後の水てきで止まる音。やめたときはすぐ止める
  - 工程が変わったとき・指を離したとき・終わったときは止める
- 相棒の声（鳴き声）は使わない。人型やコラボの子が猫の声で鳴くのは合わないため。声を鳴らしていた場面は `pet` の音にする。猫の鳴き声のファイルは `art/audio/` にしまった
- ファイルが読めないとき（artifacts のプレビューなど）は、効果音はその場で合成した音で代わりにし、BGM は流さない

**設定**

- 音のオン／オフ（BGM と効果音の両方）、BGM の音量、効果音の音量
- 音は最初のタップのあとから鳴らす（スマホの自動再生の制限への対策）
- 曲の割り当て・大きさの割合は `audio.js` の先頭にまとめる

## 4. 画面・UI設計

### 4.1 原則

- **全画面の3D＋HUD**。3D画面を枠に埋め込んだウェブページ構成はやめる。
- 画面に置かないもの：ページ見出し、英字の小見出し、フッター、サイドの情報パネル、長い説明文。
- **「その他」ボタンは作らない。** 下のボタンはどの場面も4つまでにし、入りきらないものは、関係する場所（ステータス欄、日数の横など）に置く。
- 設定は右上のボタン1か所だけ。
- 細かい設定・購入・文章が必要な場面だけ、ポップアップを出す。
- セリフや注文は、3Dの上の吹き出しで見せる。
- **フォント**：ボタン・見出し・説明は Yusei Magic（油性マジック）、セリフは Yomogi（よもぎ）。どちらも太字がないので、にせの太字は作らず、強調は大きさでつける。
- **アイコン**：下のボタンのアイコンは、ボタンごとに色を分けた丸の上に置く。

### 4.2 HUDの配置

| 位置 | 置くもの |
| --- | --- |
| 左上 | コイン・日数・スケッチブックのボタン（幅 400px 未満はアイコンだけ）（ハラハラモード中はその印も） |
| 右上 | 設定ボタン（音・ハラハラモード・セーブ・やり直し・法的表示） |
| 上中央（スマホは2段目） | 場所の切り替え（おへや／カフェ／コンビニ） |
| その下の左 | 相棒の状態。押すと相棒のメニュー（手直し）。カフェでは注文カード、コンビニではバッグの中身 |
| 下中央 | 場面ごとのボタン（4つまで。「その他」は作らない） |
| 3D上 | 吹き出し・お客さまの注文・売上の数字 |

### 4.3 画面ごとの内容

- **おへや**：ボタンは「バッグ・お風呂・おやすみ・お部屋」。相棒をタップすると反応し、左右にこするとなでる。ドラッグで少し視点が動く。
- **カフェ**：注文は吹き出しで見せる。ボタンは「メニュー・作る・運ぶ（提供後はつぎの人）・お店」。メニューの中から新しい料理を描ける。「お店」で増築。売上は数字が浮かび上がる演出。
- **コンビニ**：ボタンは「買う・新しく描く」。店員さんがカウンターの手前に立つ。
- **引っ越し先を見る**：「お部屋」から入る。ボタンは「まえ・つぎ・ここに住む・もどる」。
- **描く（ポップアップ）**：「自分で描く」と「魔法のペンにおまかせ」の2択。魔法のペンの一覧の先頭に「見本を見せる」（2.5）。
- **お絵かきエディタ**：全画面モード（HUDは隠す）。
- **はじめかた**：絵を用意 → 絵を見ながら名前と性格（選ぶだけ。「つぎへ」は別ボタン）→ 「この子でいい？」の確認画面の一本道。移動は「つぎへ」と「もどる」だけで、入れかけの内容は行き来しても残る。はじめかたの途中では閉じるボタンを出さない。
- **ミニゲーム**：3.4の枠。どれも全画面で行う。

### 4.4 端末と向き

- **スマホは縦向き（390×844程度）を基準にする。** PCは横長の画面に同じHUDを広げて置く。
- 縦画面のHUD：1段目に「コイン・日数・スケッチブック（左。幅 400px 未満はアイコンだけ）／設定（右）」、2段目に場所の切り替え、その下に相棒の状態。下にボタン4つ。
- 相棒の状態は、画面の幅に関係なく左上に置く（下のボタンと重ならないように）。
- 3Dのカメラは縦の構図を基本にする（物を奥行き方向に並べる）。縦画面では少し引いて映す。
- **カフェは店全体を映さない。** カメラはいま対応しているお客さまの席と相棒を追う。テーブルは小さく低くし、お客さまはその横に立って全身が見えるようにする（テーブルやカウンターは人物を隠さない付属品として置く）。
- PCでは注文カードを左上に、縦画面でも同じ位置に置く。
- お絵かきは全画面モードにして、縦向きでも使いやすい配置にする。全画面にするミニゲームも同じ扱いにする。

### 4.5 スマホのブラウザで遊ぶ前提の操作方針

原則：**OSやブラウザの標準ジェスチャーとぶつかる操作を、ゲームに必須の操作にしない。** 現行版は、不具合が出てから要素ごとに個別に対処していた（protectGameGestures など）。新版では最初に共通の入力の仕組みとして作る。

- **長押しを必須の操作にしない。** iOS Safariでは長押しで文字選択・ルーペ・画像の保存メニューが出る。「長押しで焼く」は「タップで火をつける→もう一度タップで止める」などに置き換える。どうしても使う場合は0.3秒程度の短い押下にとどめ、指を離したかどうかの判定は甘めにする。
- **画面の端からのスワイプを使わない。** 左右の端は「戻る」、下の端はホームバーと競合する。操作する部品は safe-area の内側に置き、端から16px程度あける。
- **ダブルタップを使わない**（拡大と競合する）。全体に `touch-action: manipulation` をかけ、連打する操作は pointerdown で判定する。
- ドラッグを使う領域（3D画面、お絵かきのキャンバス）だけ `touch-action: none` にする。ポップアップの中のスクロールは止めない。
- ゲーム画面全体に `user-select: none` と `-webkit-touch-callout: none` をかけ、画像は `draggable=false` にする。名前の入力欄などだけ例外にする。
- 入力は Pointer Events に統一する。`pointercancel`（ブラウザに操作を取られたとき）は必ず「指を離した」と同じ扱いにする。
- ピンチはお絵かきのキャンバスの拡大だけに使う。iOSはページの拡大を viewport で禁止できないので、ゲーム側で gesturestart を止める。
- 画面の高さは `100dvh` を基準にする（アドレスバーの伸び縮み対策）。引っぱって更新とバウンスは `overscroll-behavior: none` で抑える。
- 音は最初のタップで鳴らし始める（自動再生の制限への対策）。
- タップできる部品は44px以上にする。
- 「なでる」（左右にこする）はドラッグなので、3D画面の中であれば問題ない。

## 6. 技術方針

- 新規実装。3D表示は three.js を引き続き使う想定。
- ゲームの状態とルールのコードを、画面描画（3D／HUD）から分ける。
- CSSは1系統で設計する（現行のように、後から上書きするCSSを積み重ねない）。
- 絵の素材は `public/assets/` にIDの名前で置くだけで差し替えられるようにする（魔法のペンの絵、仮素材から本番素材への置き換え）。
- セーブは IndexedDB に自動保存し、JSONでの書き出し・読み込みも用意する。
- 現行版のセーブデータとの互換は取らない（提案）。
- **セーブの互換（決定）**：正式リリース（メジャーリリース）までは、セーブの形が変わっても、古いセーブとの互換は取らない。絵の場所の変更などで、前から遊んでいるセーブの見た目が少し変わってもよい（例：#24 でコラボの子の基本の絵を変えた）
- **正式リリースのあと（提案）**：リリースのときにセーブの形を固定し、セーブに入っている版番号（`v`）を見て、古い形を新しい形に順に変換する仕組み（`store.js` の読み込み時）を用意する。絵ファイルの名前を変えるときも、古い場所から新しい場所への置き換えをこの変換に入れる
- **公開**：GitHub リポジトリ（SyafuChan3333/OekakiGurashi）の `main` に入ると、GitHub Actions が `public/` だけを GitHub Pages に公開する。ビルドなし。three.js は同梱版
- **プレビュー**：artifacts。公開版とは2ファイルだけ差し替える（three.js を CDN から読む、開発用ボタンを常に出す。`preview/`）
- **開発の決まり**：リポジトリの `CLAUDE.md` にまとめる（プルリクエストは目的ごとに1つ、確認は `npm test`、など）
- **公開しない素材**：コラボの元の大きい絵や、まだ使っていない差分は `art/` に置く（`public/` の外なので公開されない）
- **開発用ボタン**：URL に `?debug` を付けたときだけ設定に出る

### 6.1 魔法のペンの絵を足すとき

いまは**絵ファイルを `public/assets/pen/` に置き、`public/js/data.js` の一覧に1行足せば、その場面の魔法のペンに並ぶ**。ただし一覧が種類ごとにばらばらで、場面によって注意点が違う。

**いまの持ち方**

| 種類 | 一覧（data.js） | ファイル | いまの数 | 足すときの注意 |
| --- | --- | --- | --- | --- |
| 相棒 | `PEN_COMPANIONS`（先頭にコラボの `VT_COMPANIONS` を含む） | `vt-*.png`（コラボ。1人7枚）、`human1〜3.svg`、`cat0〜9.png` | 16（うちコラボ3） | `{ src, name }` を1行。コラボは `vtCompanion(…)` の1行（`art/collab/README.md`） |
| カフェの料理 | `PEN_DISHES` | `food-<id>.svg` | 12 | 種類（甘いものなど）と値段も書く。お客さまが頼む種類のものだけが並ぶ |
| コンビニのごはん | `PEN_FOODS`（`SHOP_START` から作る） | 料理と同じ `food-*.svg` | 3 | `SHOP_START` に足すと商品にもなるが、**既存のセーブには出ない**（商品の一覧をセーブに写しているため） |
| おもちゃ | `PEN_TOYS`（ボール・猫じゃらし・ぬいぐるみごと） | `toy-*.svg` | 各1 | 遊び方は種類で決まるので、どの種類に足すかを選ぶ |
| ポスター | `PEN_POSTERS` | `poster-*.svg` | 2 | `{ src, name }` を1行 |
| 気持ちの記号（3.8） | なし（`scene.js` の `FEEL_LOOKS`） | `feel-note.svg`（音符）・`feel-heart.svg`（ハート）・`feel-moya.svg`（もやもや）・`feel-puku.svg`（ぷんぷんの煙） | 4 | 一覧には並ばない。**同じ名前のファイルを置き換えるだけ**で手描きに差し替わる（いまは仮の線画） |

絵の形式もそろっていない（猫は 235×256 の PNG、人型は 512×640 の SVG、料理は 320 四方の SVG など）。どれも動くが、大きさや余白がまちまちだと、並べたときやミニゲームの中で大きさがずれる。

コラボの絵（`vt-*.png`）は、いただいた元の絵が 1536×1536 で1枚約1MBと重い。公開する分は 512×512 に縮めて `public/assets/pen/` に置き、元の大きい絵は `art/collab/` に置く（#9）。表情の差分も同じ形で、1人7枚（#24）。

**相棒に表情の差分を足す手順**（3.8）

1. 差分の絵を、基本の絵と**同じ大きさ・同じ位置合わせ**で作る（差し替えたときに体がずれない）
2. `public/assets/pen/` に `<基本の名前>-<枠>.png` で置く（例：`vt-rotan-smile.png`）。枠は `talk`・`smile`・`smileTalk`・`happy`・`sad`・`angry`
3. `public/js/data.js` の相棒の行に `faces: { smile: 'assets/pen/vt-rotan-smile.png', … }` を足す。使う枠だけでよい（ない枠は代わりで埋まる）
4. `npm test` を通し、開発用ボタンで気持ちを切り替えて見た目を確かめる
5. 公開する前に、権利と見せ方を確認する（コラボの子は先方に）

**足す手順（いまの作りのまま）**

1. 絵を用意する：背景は透明、正方形、余白は少なめ。質感は「手描き」にそろえる（太めの線、塗りはべた塗り寄り）
2. `public/assets/pen/` に `<種類>-<英小文字の名前>.png`（または .svg）で置く
3. `public/js/data.js` の該当する一覧に1行足す
4. `npm test` を通し、その場面の魔法のペンの一覧をスクリーンショットで確かめる
5. プレビューに、絵ファイルと `data.js` を載せる

**守ること**

- **絵ファイルを消さない・名前を変えない**。セーブには絵そのものではなく `assets/pen/cat3.png` のような場所が入っているので、消すとその子の絵が出なくなる
- 一覧から外したいときは、一覧の行だけ消してファイルは残す（新しくは選べないが、いまいる子はそのまま）
- 同じ名前で上書きすると、すでにその絵を選んだ人の絵も変わる。仮素材を本番の絵に差し替えるときは、この方法でよい

**整理の提案（絵をよく足すようになる前に）**

- **一覧を1か所にまとめる**：`data.js` に `PEN = { companion, dish, food, toy, poster }` を作り、どの種類も「`id`・`name`・`src` ＋その種類だけの項目」という同じ形にする。絵を足す人はここだけ見ればよい
- **コンビニの商品をセーブに写さない**：はじめからある商品は一覧から読み、セーブには「自分で足した商品」だけを持つ。絵や商品を足したとき、いま遊んでいる人にも届く
- **確かめるテストを足す**：一覧の絵ファイルが全部あるか、`id` がかぶっていないか、過去に使ったファイルが消えていないかを、`npm test` で確かめる
- **絵の形式をそろえる決まり**：正方形・透明・余白の目安を決め、これから足す絵から守る。いまある絵は、本番の絵に差し替えるときにそろえる
- ファイルを種類ごとのフォルダに分けるのは、既存のセーブの場所が変わるのでやらない
